# Подтверждение email в режиме разработки

При `make up` dev-сборка Docker Compose отправляет письма в Mailpit. Код подтверждения после регистрации можно посмотреть на <http://localhost:8025>.

При локальном запуске (`make dev-api`) с пустым `SMTP_HOST` письма выводятся в лог приложения. Ищите строку `email (SMTP не настроен, письмо не отправлено)` с текстом письма.

Для реальной отправки задайте в окружении приложения `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`. В dev-конфигурации `deploy/docker-compose.yml` хост и порт явно указывают на Mailpit.

## Как подключить макет от Frontend №1

Положите готовую HTML-вёрстку письма в `internal/auth/infra/notify/templates/verify_email.html`. В тексте шаблона используйте `{{.Code}}` для шестизначного кода, `{{.Name}}` для имени и `{{.TTLMinutes}}` для срока действия в минутах.

Запустите `go test ./internal/auth/infra/notify ./internal/platform/mailer`, затем пересоберите приложение. Шаблон встраивается в бинарник. С ним письмо отправляется в двух версиях (`text/plain` и `text/html`), без него — только в текстовой. Для ручной проверки зарегистрируйте тестового пользователя, откройте письмо в Mailpit и проверьте, что код из письма подтверждает email.

# Модели для Ollama

Без скачанных моделей приложение запускается, но ответы бота и индексация базы знаний не работают (в логе при старте будет предупреждение, а вызовы модели вернут ошибку «модель не найдена»). Скачать модели из `LLM_CHAT_MODEL` и `LLM_EMBED_MODEL` (несколько ГБ):

```
make models
```

# Локальная разработка без Docker для приложения

```
make deps-up        # Postgres и Ollama в Docker
make dev-api        # Go-сервер на :8080 (или make dev-api-watch с горячей перезагрузкой)
make dev-web        # Vite на :5173, проксирует /api на :8080
```

# Тесты

```
make test           # юнит-тесты и проверка правил DDD-слоёв (internal/archtest)
make test-int       # плюс интеграционные с настоящим Postgres (нужен make deps-up)
```

`make test-int` создаёт в контейнере Postgres отдельную базу `closer_ai_test` (адрес — `TEST_DATABASE_URL`), рабочая база `closer_ai` не трогается. Тест настоящей Ollama запускается, если задан `OLLAMA_TEST_URL=http://localhost:11434` и скачаны модели.

Как устроен код (ограниченные контексты, события, фоновые задачи) — в [Архитектура DDD](Архитектура%20DDD.md).
